# My Dashboard 웹 버전 개발 지시서 (AI 개발용) > 이 문서를 AI 코딩 도구(Claude Code 등)에 그대로 주고 "이 문서대로 개발해줘"라고 지시한다. > 문서 끝 **부록**에 현재 동작 중인 로컬 버전의 전체 소스가 들어 있다. 화면·디자인·동작은 부록 소스를 **그대로 기준**으로 삼는다. --- ## 0. AI 에게 주는 지시 요약 1. 부록의 현재 소스(로컬 1인용, SQLite, Python 표준 라이브러리 서버, 순수 JS)를 기반으로 **인터넷에 공개되는 개인용 웹 서비스**로 바꾼다. 2. 화면(디자인·탭 구성·동작)은 **바꾸지 않는다.** 추가되는 화면은 로그인 페이지와 로그아웃 버튼뿐이다. 3. 저장소를 **Oracle Autonomous Database(Always Free)** 로 바꾼다. 기존 SQLite 저장소는 로컬 개발·테스트용으로 남긴다 (config 로 선택). 4. **로그인**(사용자 1명, 비밀번호 1개)을 추가한다. 로그인 없이는 화면·API 모두 접근 불가. 5. **Oracle Cloud Always Free VM** 에서 Caddy(HTTPS) 뒤에 systemd 서비스로 돌린다. 배포 파일과 설치 순서를 함께 만든다. 6. 프리티어로 충분하도록 **가볍게** 유지한다: 웹 프레임워크·프론트 빌드 도구·CDN 없이, 외부 패키지는 `oracledb` 하나만. 7. 작업 순서와 완료 기준은 13장, 테스트는 14장을 따른다. 모르는 값(도메인, DB 접속 정보)은 config/환경변수로 빼고 임의로 정하지 않는다. --- ## 1. 목표와 범위 | 항목 | 내용 | |---|---| | 사용자 | 나 1명 (회원가입 없음) | | 접속 | `https://<내 도메인>` - PC·휴대폰 브라우저 | | 서버 | Oracle Cloud Infrastructure(OCI) Always Free Compute VM | | DB | OCI Always Free Autonomous Database (Transaction Processing 또는 JSON, 23ai/19c 어느 쪽이든) | | 비용 | 0원 (Always Free 한도 안) - 도메인 비용만 | | 데이터 | 개인 일정·할 일·메모 (회사 정보 없음) | | 제외 | 다중 사용자, 회원가입, 비밀번호 찾기 메일, 실시간 동기화(WebSocket), 모바일 앱 | --- ## 2. 현재 앱(로컬 버전) 요약 부록 소스가 정답이다. 아래는 빠르게 파악하기 위한 요약. ### 2.1 구조 ``` my_dashboard/ ├─ app.py         진입점. 기본=pywebview 전용 창, --web=브라우저 모드. config.json 로드 ├─ server.py      ThreadingHTTPServer. 정적 파일 + REST API(1건 단위 upsert/delete). Host/Origin 검사 웹 버전에서 **pywebview·PyInstaller 관련 코드(run_window, attach_console, FROZEN/_MEIPASS 처리)는 제거**해도 된다. 서버에서는 `python app.py` 하나로 웹 서버만 뜨면 된다. ### 2.2 화면(탭)과 기능 상단 바: 브랜드 `My Dashboard` · 탭 7개 · 오른쪽에 저장 상태 표시, `내보내기`, `가져오기`, 테마 전환(◐). **웹 버전은 여기에 `로그아웃` 버튼을 추가.** | 탭(해시) | 기능 | |---|---| | 보드 `#board` | 칸반 3열 준비(todo)/진행중(doing)/완료(done). HTML5 드래그로 열 이동·열 안 순서 변경(rank), 열마다 빠른 추가 입력, 분류 필터, 완료 열은 최근 14일만(그 이전은 할 일 탭 '완료' 필터 안내), 카드 클릭=수정 | | 달력 `#calendar` | 월간 달력(일=빨강, 토=파랑, 공휴일=빨강+이름), 여러 날 일정, 반복 일정(없음/매일/평일/매주/매월/매년 + 종료일), 할 일 마감 표시, 오른쪽 날짜 패널(그 날 일정·할 일, 일정 추가, 휴일·휴무일 지정/해제) | | 루틴 `#routine` | 매일 체크하는 루틴 목록(추가·수정·삭제·순서 변경), 오늘 체크리스트, 최근 기록 표(날짜×루틴, 셀 클릭으로 체크) | | 메모 `#notes` | 왼쪽 목록(고정 우선, 최근 수정순) + 오른쪽 편집기(제목·본문), 입력 500ms 후 자동 저장, 고정·삭제 | | 스니펫 `#snippets` | 카드 그리드. 제목·분류(자유 입력)·언어(자동 판단/SQL/일반 텍스트)·코드·메모. SQL 은 정규식 기반 구문 강조(키워드·함수·문자열·숫자·주석·힌트·바인드변수·식별자), 복사 버튼, 분류 필터·검색 | 공통 동작: - **저장**: 변경 즉시 1건 단위 API 호출. 같은 경로는 디바운스되어 마지막 요청만 전송(`send()`). 창을 닫을 때 대기 중인 PUT 은 `sendBeacon`(POST)으로 전송. - **저장 상태**: 상단 `저장 중… / 저장됨 HH:MM:SS / 저장 실패…`. - **자정 갱신**: 1분마다 날짜 확인, 바뀌면 다시 그림. ### 2.3 상태값 규칙 (할 일) - `status` ∈ `todo | doing | done`, `done`(bool) 과 항상 일치: `done=true ⇔ status='done'`. | `secure_cookie` | `false` | HTTPS 뒤에서는 true (쿠키 Secure 속성) | | `trust_proxy` | `false` | true 면 클라이언트 IP 를 `X-Forwarded-For` 마지막 값에서 읽음 (Caddy 뒤에서만) | | `data_dir` | 앱 폴더/data | auth.json, 백업 저장 위치 | 환경변수 (`/etc/mydashboard.env`): ``` ORA_USER=MYDASH ORA_PASSWORD=... ORA_DSN=(description=(retry_count=20)(retry_delay=3)(address=(protocol=tcps)(port=1522)(host=adb.ap-chuncheon-1.oraclecloud.com))(connect_data=(service_name=xxxx_mydash_tp.adb.oraclecloud.com))(security=(ssl_server_dn_match=yes))) # 지갑(mTLS) 방식을 쓸 경우에만 ORA_WALLET_DIR=/var/lib/mydashboard/wallet ORA_WALLET_PASSWORD=... ``` --- ## 6. 데이터 모델 ### 6.1 JS ↔ DB 매핑 (현재 store.py 의 TABLES 와 동일하게 유지) | 컬렉션 | 테이블 | 필드(JS → 컬럼, 타입) | |---|---|---| | todos | TODOS | id, title, due, priority, tag, memo, done(bool), doneAt→done_at, createdAt→created_at, status, rank→rank_no(num) | | events | EVENTS | id, title, date→start_date, endDate→end_date, time→start_time, repeat→repeat_rule, until→repeat_until, color, memo, dday(bool) | | notes | NOTES | id, title, body, pinned(bool), updatedAt→updated_at | | snippets | SNIPPETS | id, title, tag, code, memo, lang, updatedAt→updated_at | | routines | ROUTINES | id, title, (sort_order: 배열 순서) | | routineLog | ROUTINE_LOG | `{ "YYYY-MM-DD": [routineId, ...] }` ↔ (log_date, routine_id) | | holidays | HOLIDAYS | `{ "YYYY-MM-DD": "이름" }` ↔ (hdate, name) | - 날짜·시각은 현재처럼 **문자열**(`YYYY-MM-DD`, ISO 시각)로 저장한다. JS 쪽 로직을 바꾸지 않기 위함. - bool 은 `NUMBER(1)` 0/1, API 응답에서는 JSON true/false. - 빈 문자열: **Oracle 은 `''` 를 NULL 로 저장**한다. 조회 시 NULL → `''` 로 바꿔 돌려줘야 JS 가 기존과 똑같이 동작한다 (text 타입 컬럼 전부). 이 처리를 빠뜨리면 화면에 `null` 이 찍힌다. ### 6.2 Oracle DDL (store_oracle.py 가 최초 실행 시 없으면 생성) ```sql CREATE TABLE todos (   id          VARCHAR2(64)  PRIMARY KEY,   title       VARCHAR2(1000 CHAR),   due         VARCHAR2(10),   priority    VARCHAR2(10),   tag         VARCHAR2(100 CHAR),   memo        VARCHAR2(4000 CHAR),   done        NUMBER(1) DEFAULT 0 NOT NULL,   done_at     VARCHAR2(40),   created_at  VARCHAR2(40),   status      VARCHAR2(10) DEFAULT 'todo' NOT NULL CHECK (status IN ('todo','doing','done')),   rank_no     NUMBER DEFAULT 0 ); CREATE INDEX ix_todos_due ON todos(due); CREATE TABLE events (   id           VARCHAR2(64) PRIMARY KEY,   title        VARCHAR2(1000 CHAR),   start_date   VARCHAR2(10),   end_date     VARCHAR2(10),   start_time   VARCHAR2(5),   repeat_rule  VARCHAR2(20),   repeat_until VARCHAR2(10),   color        VARCHAR2(20),   memo         VARCHAR2(4000 CHAR),   dday         NUMBER(1) DEFAULT 0 NOT NULL ); CREATE TABLE notes (   id          VARCHAR2(64) PRIMARY KEY,   title       VARCHAR2(1000 CHAR),   body        CLOB,   pinned      NUMBER(1) DEFAULT 0 NOT NULL,   updated_at  VARCHAR2(40) ); CREATE TABLE snippets (   id          VARCHAR2(64) PRIMARY KEY,   title       VARCHAR2(1000 CHAR),   tag         VARCHAR2(100 CHAR),   code        CLOB,   memo        VARCHAR2(4000 CHAR),   lang        VARCHAR2(20),   updated_at  VARCHAR2(40) ); CREATE TABLE routines (   id          VARCHAR2(64) PRIMARY KEY,   title       VARCHAR2(1000 CHAR),   sort_order  NUMBER DEFAULT 0 ); CREATE TABLE routine_log (   log_date    VARCHAR2(10),   routine_id  VARCHAR2(64),   CONSTRAINT pk_routine_log PRIMARY KEY (log_date, routine_id) ); CREATE TABLE holidays (   hdate  VARCHAR2(10) PRIMARY KEY,   name   VARCHAR2(200 CHAR) ); ``` - 컬럼 이름은 처음부터 Oracle 예약어(`DATE`, `TIME`, `RANK`, `REPEAT` 등)를 피해 지었으므로 그대로 쓴다. - 테이블이 비어 있으면 seed(공휴일·기본 루틴)를 넣는다 (현재 store.init 과 동일). - 앞으로 컬럼이 추가되면 현재 SQLite 의 `ADDED_COLUMNS` 방식처럼 `USER_TAB_COLUMNS` 를 확인해 `ALTER TABLE ADD` 한다. ### 6.3 DB 계정 ADMIN 으로 앱을 돌리지 않는다. Database Actions(SQL 워크시트)에서 ADMIN 으로 한 번 실행: ```sql CREATE USER mydash IDENTIFIED BY "<강한 비밀번호>" DEFAULT TABLESPACE data QUOTA 1G ON data; GRANT CREATE SESSION, CREATE TABLE TO mydash; ``` --- ## 7. 저장소 구현 (store_oracle.py) `store.py` 의 `Store` 와 **같은 공개 메서드·반환 형태**로 만든다. server.py 는 어느 저장소인지 몰라야 한다. | 메서드 | Oracle 구현 메모 | |---|---| | `init(data_dir, seed_dir)` | 테이블 없으면 DDL 실행(`USER_TABLES` 확인), 비어 있으면 seed 입력, todos status/done 보정 UPDATE | | `all()` | 7개 테이블 조회 → 현재와 같은 dict. CLOB 은 문자열로(`oracledb.defaults.fetch_lobs = False`), NULL→'' | | `upsert(coll, item)` | `MERGE INTO t USING (SELECT :id id FROM dual) s ON (t.id = s.id) WHEN MATCHED THEN UPDATE ... WHEN NOT MATCHED THEN INSERT ...`. 알 수 없는 필드는 무시, 타입 변환(bool→0/1, num→float) | | `delete(coll, id)` | routines 삭제 시 routine_log 의 해당 루틴도 삭제 (한 트랜잭션) | | `set_routine_order(ids)` | executemany 로 sort_order 갱신 | | `set_routine_log(date, rid, on)` | on: MERGE(없으면 INSERT) / off: DELETE | | `set_holiday(date, name)` | name 있으면 MERGE, 없으면 DELETE | | `replace_all(data)` | **교체 전 현재 데이터를 JSON 백업 파일로 저장** → 한 트랜잭션으로 전체 DELETE + INSERT(executemany) → 실패 시 rollback | | `backup_once_a_day()` | `data_dir/backup/dashboard_YYYY-MM-DD.json` 에 `all()` 결과 저장, 30일 지난 파일 삭제 | 공통 규칙: - 연결: `oracledb.create_pool(user, password, dsn, min=1, max=4, increment=1)` (+ 지갑 방식이면 `config_dir/wallet_location/wallet_password`). 요청마다 `pool.acquire()`. - 모든 SQL 은 **바인드 변수**(`:name`). 테이블·컬럼 이름은 TABLES 화이트리스트에서만 가져와 문자열에 넣는다. - 쓰기는 명시적 commit, 예외 시 rollback. - DB 가 정지(7일 미사용 자동 정지)되어 연결이 안 되면 API 는 503 + `{"error":"db unavailable"}` 를 돌려주고, 화면 상태줄에 "DB 에 연결할 수 없습니다" 가 뜨게 한다. - **연결 유지(keepalive)**: 서버 스레드에서 12시간마다 `SELECT 1 FROM dual` 실행 + 하루 한 번 `backup_once_a_day()`. (Always Free ADB 는 7일간 활동이 없으면 정지되고, 정지 후 90일 지나면 삭제된다. 이 쿼리가 '활동'으로 인정되는지는 배포 후 OCI 콘솔에서 확인할 것 - 확인 전까지는 정지 알림을 받으면 콘솔에서 수동 시작.) SQLite 저장소(`store.py`)는 로컬 개발·테스트용으로 유지하고, 같은 테스트를 두 저장소에 모두 돌릴 수 있게 한다. --- ## 8. API 현재 API 는 그대로 두고 인증 관련만 추가한다. 모두 JSON. | 메서드 | 경로 | 인증 | 설명 | |---|---|---|---| - `python app.py --set-password` → getpass 로 두 번 입력받아 `data_dir/auth.json` 에 저장 (scrypt n=2^14,r=8,p=1, salt 16바이트, 권한 600). - 저장 시 쿠키 서명 키(secret)도 새로 만든다 → **비밀번호를 바꾸면 기존 로그인 모두 무효**. - 최소 길이 12자 검사. ### 9.2 세션 - 쿠키 `md_session = "<만료시각>.<HMAC-SHA256 서명>"`, `HttpOnly; SameSite=Strict; Path=/; Max-Age=30일; Secure`(secure_cookie=true 일 때). - 서버 재시작해도 유지(서명 방식이라 서버 메모리에 세션 저장 안 함). - 사용 중 자동 연장: 발급 후 하루 이상 지난 쿠키로 요청이 오면 응답에 새 쿠키를 실어 보냄. - 로그아웃은 쿠키 삭제. (모든 기기 강제 로그아웃 = 비밀번호 재설정) ### 9.3 접근 제어 (server.py dispatch 맨 앞) 1. Host/Origin 검사 (현재 로직 유지, allowed_hosts 에 도메인 추가). 2. `auth=true` 일 때 로그인 없이 허용하는 경로: `GET /login.html`, `GET /style.css`, `GET /favicon.ico`, `POST /api/login`, `GET /api/session`. 나머지는:    - `/api/*` → 401 `{"error":"login required"}`    - 그 외 GET → 302 `Location: /login.html` 3. 상태를 바꾸는 요청(PUT/POST/DELETE)은 Origin 헤더가 있으면 반드시 허용 도메인이어야 함(현재 로직) + SameSite=Strict 쿠키 → CSRF 방지. ### 9.4 로그인 시도 제한 - IP별 15분에 5회 실패, 전체 1시간에 30회 실패 시 429. 실패한 요청에는 응답 전 0.5~1초 지연. - IP 는 `trust_proxy=true` 일 때 `X-Forwarded-For` 의 마지막 값(Caddy 가 붙인 값), 아니면 소켓 주소. - 로그인 성공·실패를 서버 로그에 남김(IP, 시각). 비밀번호는 절대 로그에 남기지 않음. ### 9.5 응답 보안 헤더 (모든 응답) ``` X-Content-Type-Options: nosniff X-Frame-Options: DENY Referrer-Policy: same-origin Content-Security-Policy: default-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; frame-ancestors 'none' Cache-Control: no-store   (현재와 동일) ``` (HSTS 는 Caddy 에서 설정. app.js 에 인라인 스크립트가 없으므로 script-src 'self' 로 충분 - login.html 도 스크립트를 별도 파일 `login.js` 로 둘 것.) ### 9.6 기타 - 요청 본문 최대 20MB(가져오기 고려), 넘으면 413. - 디렉터리 목록 응답 금지(SimpleHTTPRequestHandler 의 list_directory 를 404 로 막기). - 오류 응답에 스택트레이스·SQL 노출 금지(현재처럼 `server error` 만). ### 9.7 프론트 변경 (app.js) - `request()` 에서 401 이면 상태줄에 "로그인이 만료되었습니다 — 새로고침 후 다시 로그인하세요" 표시 (대기 중인 메모 내용을 잃지 않도록 **자동 이동하지 않는다**). - `init()` 에서 `/api/all` 이 401 이면 `location.replace('/login.html')`. - `/api/session` 결과 `auth=true` 면 상단 도구 영역에 `로그아웃`(ghost 버튼) 표시 → `POST /api/logout` 후 login.html 로 이동. - 서버 연결 실패 문구의 "MyDashboard.exe 로 다시 실행하세요" 는 "서버에 연결할 수 없습니다" 로 변경. --- ## 10. 배포 (OCI) ### 10.1 OCI 준비 1. Always Free 계정. (가능하면 **Pay As You Go 로 업그레이드** - 무료 한도 안이면 0원이고, 유휴 Always Free VM 회수 대상에서 빠진다. 업그레이드 안 하면 7일간 CPU·네트워크·메모리 사용률이 매우 낮은 VM 은 회수될 수 있음.) 2. Autonomous Database 생성: Always Free 체크, 워크로드 Transaction Processing.    - 네트워크: "보안 액세스: 허용된 IP 및 VCN" 선택 → VM 의 공인 IP 만 허용. 이 경우 mTLS 필수 해제 가능 → **지갑 없이 TLS 접속**(ORA_DSN 에 TLS 접속 문자열).    - 또는 mTLS 유지 + 지갑 다운로드(thin 모드는 지갑의 `ewallet.pem`, `tnsnames.ora` 사용). 3. Compute 인스턴스: Ampere A1 Flex 1 OCPU/6GB, Ubuntu 24.04, 공인 IP. 4. VCN 보안 목록(Security List)에 수신 TCP 80, 443 허용 (22 는 내 IP 만 권장). 5. **VM 내부 방화벽도 열어야 함** (OCI Ubuntu 이미지는 iptables 로 막혀 있음):    ```bash    sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 80 -j ACCEPT    sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 443 -j ACCEPT    sudo netfilter-persistent save    ```    (Oracle Linux 이미지면 `firewall-cmd --permanent --add-service=http --add-service=https && firewall-cmd --reload`) 6. 도메인 DNS 에 A 레코드 → VM 공인 IP. ### 10.2 서버 설치 ```bash
